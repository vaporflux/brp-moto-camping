# build/ — offline data pipeline

The deployed site stays a single static file with no build step. This generator runs in
the repo, offline, the way `v1/build.py` did, and bakes a validated bundle the page
inlines. Nothing here touches the network at runtime or at build time.

```
python3 build/derive.py      # -> data/derived/planner-data.json, quality-report.json
python3 build/test_data.py   # 25 regressions, each pinning a bug found in this pass
```

## Why the milepost model was rebuilt

`data/parkway.json` measures 451.74 mi against an official 469.1. The shipped datasets
resolved that by scaling everything by `469.1/451.74`, which assumes the 17.4 mi deficit
spreads evenly. It does not — the centerline is distance-resampled at ~0.17 mi, so the
loss is chord-vs-arc error and concentrates in curves.

Measured against 8 independent controls (campgrounds whose geocoded position sits within
0.5 mi of the road, so their published access milepost pins a real place):

| model | mean error | max error |
|---|---|---|
| shipped uniform scale | 1.85 mi | 3.58 mi |
| calibrated, leave-one-out | **0.34 mi** | **0.98 mi** |

Two stages: chord→arc recovery (physics, no fitting, recovers ~5 of the 17.4 mi), then
monotone piecewise-linear calibration through the controls. Accuracy is reported
leave-one-out because interpolating through your own knots gives zero residual and means
nothing.

**Caveat that matters:** there is no interior control between MP 0 and 177.7. Virginia
mileposts are interpolated between the northern terminus and Meadows of Dan, so error
there is unmeasured rather than small. Adding one surveyed control anywhere in Virginia
would do more for accuracy than any change to the method.

## Why `parkway_segs.json` is superseded

It was cut using the uncalibrated model, so every closure gate sits 2–3 mi from the NPS
milepost it claims to represent. Since `closures.json` carries real NPS mileposts,
`network.py` re-cuts the centerline from those numbers instead. Gates now land on the
published milepost exactly, to within the model's ~0.34 mi.

The shipped VA fuel anchors were checked and found to be exact centerline vertices —
generated by walking the uncalibrated model, not surveyed — so they carried the same
error. All 29 anchors are recomputed, including the 16 NC records that shipped with none.

## Two axes, never collapsed

`confidence` answers *does a pump exist here* (a claim about the world).
`access_class` answers *can a rider get there in 2026* (a claim about the road network).
Every combination occurs in this dataset, so the code keeps them separate and derives a
display grade from the pair rather than overwriting one with the other.

A closure blocks an *approach*, not a *destination*. Campgrounds sit on surface roads and
mostly stay open when the Parkway beside them shuts — filtering stops by "milepost falls
inside a closure" deletes 5 campgrounds including 2 of the 4 motorcycle camps. Shaping
points get the strict rule; stops get the nuanced one.

## Junction coverage is partial, by necessity

`SPEC.md` §5.5 makes junction positions the core of the GPX exporter. `data/` has none.
The intended source, OSM relation 55450, is unreachable from this environment —
`overpass-api.de` is refused by egress policy. `junctions.py` assembles the 33 crossings
the repo does know (29 published fuel exits + 4 closure detour roads), tags each with
provenance, and measures the blind spots: the longest run with no known junction is
31.3 mi. The exporter must treat spacing as the fallback that carries those stretches,
not as belt-and-braces on top of complete data. See `spacing_requirement()`.
